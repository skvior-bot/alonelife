### 交互与 UI

> 交互入口的分类见 `策划案.md` → 十、交互物
> 时间规则：**时间驱动**。玩家不断做事件、消耗分钟，直到睡觉。结算器最多排 4 个事件 = 批量上限，不是每日上限。

---

#### 一、整体思路：一机走天下

这款游戏的操作核心只有两块：

1. **手机** —— 信息中枢。看时间、看同伴、看事件表、存档、网购、点外卖、发视频，全在这里
2. **事件结算器** —— 行为中枢。所有真正改变数值的操作都要经过它

**房间只是"入口"**。点击电脑/床/书架/门，本质是往结算器里丢一个事件。所以场景可以很少，交互可以很深。

> 这也符合主角的人设：一个能不打电话就不打电话的人，所有事都用手机办。

---

#### 二、主界面（标题页）

- 标题位于上方正中心，巨大的标题 logo
- 四个按钮位于下方，从左到右：**开始游戏 / 继续游戏 / 设置 / 退出游戏**
- **主界面最终形态**：左边《独居生活》、右边《孤独之旅》，两个主角背靠背，各自看向自己那边的天空

> 不做二周目。原案里"新的轮回"这个词已删除 —— 真结局之后只有后日谈（补关键剧情），没有 NG+。

---

#### 三、手机（核心界面）

**任何时候点右下角的手机图标或按快捷键打开。** 打开时不消耗时间。

##### 首页（锁屏 → 主屏）

主屏做成"小组件"式布局，一眼能看完全部状态：

| 组件 | 内容 |
|------|------|
| **时间组件**（最大） | 当前日期 / 星期 / 剩余天数、当前时段（早上/上午/中午/下午/傍晚/晚上/深夜）、精确时间 |
| **体力** | 体力条 + 当前效率档位（×1.0 / ×0.85 / ×0.65 / ×0.35） |
| **灵感** | 灵感条。**低于 20 时变红**——这是"该出门了"的信号 |
| **完成度** | 总进度条 + 四维小条 |
| **金钱** | |
| **粉丝** | 直播是主要收入，必须随时看得到 |
| **同伴**（三个头像） | 头像带状态角标：●在线 / ○睡觉 / ！有事找你 / 心情表情（沮丧·普通·开心） |

> 设计要点：**剩余天数、体力档位、灵感**三样必须一眼看到。它们分别对应三种压力：总时间、今天的状态、能不能干活。

##### 应用列表

| 应用 | 功能 |
|------|------|
| **聊天** | 三名同伴 + 家人。点头像 → 进入聊天 |
| **事件表** | 所有已解锁的事件，按地点分类 |
| **网购** | 日常 / 娱乐 / 设备 / 配件 |
| **外卖** | 点吃的（等于便利店/餐馆的快捷入口） |
| **视频** | 发布视频（已通关游戏 / 已看完动画） |
| **图鉴** | CG / 音乐 / 已完成的作品 |
| **存档** | 手动存 5 个槽，读档 |
| **设置** | 音量、文字速度、画面 |

#### 四、聊天界面（同伴状态）

**点进某个同伴的聊天，就是她的"角色页面"。** 不需要单独做角色界面。

```
┌─────────────────────────────┐
│  ← 许眠                  ⋮  │
├─────────────────────────────┤
│  [头像]  好感 ██████░░░░ 42/60│
│          阶段：第二段剧情已过 │
│          美术能力 7  ▲       │
│          心情：有点累        │
│                             │
│  ── 昨天的消息 ──            │
│  许眠：这个你看看            │
│  你：好                      │
├─────────────────────────────┤
│ [聊天 15min] [一起出门]       │
└─────────────────────────────┘
```

要显示的东西：

| 项 | 说明 |
|----|------|
| 好感条 + 具体数值 | 玩家必须知道自己离下一段剧情还差多少 |
| 阶段 | 招募中 / 第一段 / 第二段 / 第三段 / 满好感 |
| **当前能力值** | 直接对应她那一维的开发速度 —— 这是玩家最关心的数字 |
| 心情 | 沮丧 ×0.9 / 普通 ×1.0 / 开心 ×1.1。每天醒来回到普通 |
| 喜好 | 聊天选话题、一起出门选地点的依据 |
| 下一步 | "她好像有事想说" = 好感到了，可以触发剧情了 |

> **"下一步"这一栏很重要**：没有它，玩家不知道什么时候该去找她，好感系统就变成了盲盒。

#### 五、事件表（原"日历"）

按**地点**分类，而不是按日期。因为玩家关心的是"我这会儿能干什么"，不是"几号有什么"。

```
┌─────────────────────────────┐
│  事件表              全部 ▾  │
├─────────────────────────────┤
│  🏠 家里                      │
│   · 游戏开发（程序/美术/音乐/文案）│
│   · 看动画 · 玩游戏 · 看课程   │
│   · 直播 · 发视频 · 网购       │
│   · 睡觉                      │
│  🏪 便利店      [现在开放 ✓]   │
│   · 打工（按营业日）           │
│   · 买东西                     │
│  📚 书店        [18:00 关门]  │
│   · 买书 · 回收 · 打工         │
│   · ⭐ 许眠好像在这里           │
│  🌳 公园                       │
│   · 散步（恢复灵感）           │
│   · ⭐ 唐梨在弹琴              │
└─────────────────────────────┘
```

- **⭐ = 同伴在这里**，这是"该出门了"的最高优先级信号
- 灰色 = 现在做不了（店关了 / 体力不够 / 钱不够），鼠标悬停显示原因
- 参考《学生时代》《火山的女儿》的做法：**地点 + 事件列表**，不要做成传统的月历

> 原案的"日历"其实是"活动表"。玩家在 SLG 里关心的从来不是日期，是**"今天还能做什么"**。

#### 八、地点切换

点击门 → 弹出可前往地点（不含当前所在地）→ 选择 → 结算 → 到达

| 出发地 | 可前往 | 耗时 |
|-------|--------|------|
| 家 | 书店 / 餐馆 / 便利店 / 公园 / 专业道具店 | 10 / 10 / 5 / 10 / 15 分钟 |
| 书店 | 家 / 专业道具店 | 10 / 5 分钟 |
| 专业道具店 | 家 / 书店 | 15 / 5 分钟 |
| 餐馆 / 便利店 / 公园 | 家 | 10 / 5 / 10 分钟 |
| 地下通道 | 家 | 15 分钟（周末唐梨在那儿） |

- **距离真的有区别**，这是时间驱动模型的好处
- 一次出门可以连续访问多个地点再回家，时间照常累加

#### 十、事件结算器（核心）

**整个游戏的操作心脏。** 所有改变数值的行为都在这里落地。

```
┌──────────────────────────────────────────┐
│                                      ✕   │
│  ┌────┐ ┌────┐ ┌────┐ ┌────┐            │
│  │程序│ │程序│ │程序│ │程序│   [ 结算 ]  │
│  │ 1h │ │ 1h │ │ 1h │ │ 1h │            │
│  └────┘ └────┘ └────┘ └────┘            │
│   心流×1.0  心流×1.0  心流×1.05 心流×1.10 │
├──────────────────────────────────────────┤
│ 预计：10:30 → 14:30                       │
│ 体力 100→76  ⚠ 从第 4 小时起掉到 ×0.85   │
│ 灵感 60→20（够用）                        │
│ 完成度 +0.8%（程序）                      │
└──────────────────────────────────────────┘
```

- 最多 4 格。**这是"一次处理几件事"的批量上限，不是每天的上限**
- 一批合计不能超过 **16 小时 40 分**（满体力耗到空的时长），超了拆成两批
- 一天可以结算任意多次，直到睡觉
- **结算前**可以点方框取消（后方事件前移）；**点了「结算」就一口气算完，不可打断**
- 结算过程用小动画逐条播，**可以跳过**
- 右上角 X → 清空退出，无数据变化
- **连续开发同一维度会累计"心流"**：第 1~2 小时 ×1.0、第 3 小时 ×1.05、第 4 小时 ×1.10、第 5 小时 ×1.15、第 6 小时起封顶 ×1.20。换维度或做别的事就清零
- 支持"记住上次方案"，一键重排

**必须实时预览（没有这个玩家就是盲选）：**

1. 结算后的时间（几点，会不会过 24:00 变熬夜）
2. 体力会掉到哪一档（效率会不会从 1.0 掉到 0.85）
3. 灵感会不会耗尽（耗尽后的小时是 ×0.5）
4. 这一批推进多少完成度（四维分开）
5. 总共花掉多少时间

#### 十五、一次确认，一次播完：内层的操作界面

内层每一次行动都长这样：

```
┌──────────────────────────────┐
│  落雷  ｜ 第 7 / 20 帧（正在播）│
├──────────────────────────────┤
│                              │
│      （帧序列在播，播完定格）   │
│                              │
├──────────────────────────────┤
│  [ 确认动作 ▼ ]  敌人：▓▓▓░░  │
│  ⚙ 连播模式                  │
└──────────────────────────────┘
```

- **玩家按一次「交互」= 确认一个动作 → 该动作的帧序列一次播完 → 世界走掉对应帧数 → 停住**
- 不确认的时候**整个画面定格**，主角也不做待机呼吸。只有主角动，世界才动
- 底部进度条同时显示：当前帧 / 总帧数、敌人的行动进度
- 右下角常驻「跳过动画」开关（教程结束后才出现）

> 为什么不是逐帧：走一格要按 4 下，过一个房间要按上百下，手会废。
> **世界只在主角行动时流动**这一条没有变，变的是"一次行动"的粒度：从 1af 变成"一个完整动作"。

**操作成本就是帧数**：3~8 帧的动作播完很快，20~30 帧的魔法按一次也只要几秒 —— 帧数现在是**世界的成本**，不是**手指的成本**。

#### 十六、教程界面

教程不长在独立场景里，**全部长在序章的真实流程里**。每一课只教一件事，教完立刻让玩家用。

| # | 教什么 | UI 上的做法 |
|:--:|-------|-----------|
| 1 | 点击交互 | 高亮可点物，其余压暗 |
| 2 | 事件结算器 | **只给 1 格**，强制结算一次 |
| 3 | 时间会过去 | 结算后时间条动画 + 日历翻页 |
| 4 | 体力与灵感 | 强制让灵感见底，弹一次"效率腰斩"提示 |
| 5 | 怎么恢复 | 引导去吃东西 / 看一集动画 |
| 6 | 手机 | 教存档、事件表 |
| 7 | 完成度 | 回到电脑看四维进度条 |

> 教程只教**基本操作和关键设计**，其余交给玩家自己摸索。不硬推玩家去哪、不做长引导。

> 第 4 课是全教程里最重要的一课：**必须让玩家亲身体验一次"写不动了"**。
> 只看数字不会懂，摔一次才懂。

#### 十七、UI 框架要点

- 交互 → 选择项目 → 放入结算器 → 结算 → 更新数据
- 不结算退出则不触发任何事件、不改变数据
- **所有选项都要标出要花多少时间**，包括移动和一起出门 —— 时间才是这个游戏的货币
- 每个事件都要显示"它给你什么"，尤其是**灵感**，因为灵感是玩家规划的隐性成本

#### 十八、v10 定论：自由探索与痕迹的界面要求

> 本节只增加 v10 新增的界面要求，前十七节的手机、结算器、图鉴、工作台、教程规格全部有效。

##### 1. 地点探索：人是可选，不是必答题

地点界面里，同伴作为**可选交互点**出现，不遮挡其它行动：

- 她在场时给一个可见提示（人形图标 / 一行字），**但不弹窗、不拦路**。
- 玩家可以一整天不进任何地点，也可以进了地点只买东西不和她说话。
- 提示不能做成倒计时或"限时出现"的紧迫设计——**错过一次不是惩罚**，下次她还会在别的地方出现。

##### 2. 相遇与招募必须是两次确认

| 步骤 | 界面 | 玩家的动作 |
|---|---|---|
| 遇见 | 地点内的交谈入口 | 主动点击才开始对话 |
| 邀请 | 满足合作条件后出现"要一起做吗"选项 | 主动选择 |
| 确认 | 对方答应后，明确一次"开始一起做" | 主动确认 |

> 任何一步都不能由系统自动完成。旧文档里"好感够了自动进队"的做法全部作废。

##### 3. 痕迹要在界面上看得见

四个位置各自承担一件事：

| 位置 | 显示什么 | 更新时机 |
|---|---|---|
| 房间 | 买过的设备、桌上的稿件、同伴带的物件 | 立即，下次进屋就变 |
| 工作台 | 设备升级的阶段变化、进度状态 | 购买/升级后 |
| 图鉴 | 作品封面网格、进度条、完成短评 | 看完/购买后 |
| 手机 | 联系人、聊过的话题、当天心情 | 每次状态变化 |

**不要新做"痕迹值"面板。** 痕迹就是这些东西本身，加一个计数器反而把主题变成了任务。

##### 4. 第 7 天回望

七日小样末尾出一屏轻量回望，最多 3～5 条记忆片段。要求：

- 只列**真实发生**的事件，带日期。
- 没认识同伴也要有内容（独自过的日子、做完的作品、买下的设备）。
- 一屏放完，不做长演出；100 天完整版的蒙太奇试玩后再定。

数据结构见 `事件与行动.md` → 回忆闪回接口。

##### 5. 暂缓

七日小样的按钮位置、字号、配色都不锁死。先把可玩性和痕迹做出来，视觉在作者试玩后重新设计。参考稿见 `美术与场景.md` → 美术与 UI 规范。

#### 十九、交互结构：点物体 → 展开事件（2026-11-05 作者确认）

> 这一节是**核心结构定义**，实现在 `scripts/managers/ActionLibrary.gd` + `scripts/ui/life_screen.gd`。

##### 1. 两级结构

```
点物体（不耗时）
   └─ 弹出该物体的事件列表（小窗，贴在物体下方）
        └─ 选中一个事件 → 进入结算器（耗时才发生）
```

- **点物体本身不消耗时间、不产生事件**。它只是展开下一层。
- **只有事件才消耗资源**（时间、体力、金钱、灵感）。
- 所以「点电脑」不花时间，「程序开发 1 小时」才花时间。

##### 2. 结算器的显示规则

- **没事件时不出现**。放在屏幕上的常驻槽位会让界面一直很吵。
- 一旦放入事件就出现，**小巧、贴着触发位置**，不做全屏面板。
- 点某个格子 = 清空该格，后面的往前补。
- 一批最多 4 项（批量上限，不是每日行动上限）。

##### 3. 未解锁的内容一律不显示

- 还没到解锁天数的整机、还没买到的高级书、还没读过的作品，**不出现在列表里**。
- 不显示成灰色的「未解锁」，直接不出现。列表短比列表全更好用。

##### 4. 列表尽量横向

- 同层选项横向排开，纵向滚动越少越好。
- 一个物体下的事件超过 6 条时才需要滚动。

##### 5. 睡觉不常驻界面

- 睡觉**不做常驻按钮**，藏进「点床」展开的选项里（作者 2026-11-05 要求）。
- 睡觉不是事件，不进结算器；它直接结束今天。
- **是否限制必须在出租屋才能睡：未确认。** 目前未加地点限制。

##### 6. 移动是事件

- 「前往某地」要走结算器、消耗时间（家→书店 10 分钟、家→便利店 5 分钟）。
- 同一批里重复前往同一地点，**只计第一次的耗时**（人已经到了）。

### 七日试玩验收

> 这是给实际开发者的**待试玩实施方案**，不是作者确认的逐日固定剧情；严禁按指定日期强制玩家与同伴见面。

#### 一、切片体验目标

用同一套时间驱动结算器，让玩家在**房间、书店、公园、便利店**之间安排自己的七天。最终回望能展示不同选择产生的不同经历。工程优先在 Godot 实现，不要求立刻完成所有 100 天、外层全部结局或内层战斗。

#### 二、最低可玩范围

| 子系统 | 最低内容 | 验收 |
|---|---|---|
| 标题与姓名 | 开始/继续；2～3 汉字姓名；保存 `player_name` | 显示与读档正确，不与殇可/许眠/唐梨/温野硬编码重名 |
| 时间与资源 | Day 1～7；当前时刻、体力、灵感、金钱、开发进度 | 时间按行为实际分钟推进，没有每日固定四次行动限制 |
| 结算器 | 1 批最多四项；显示消耗预览 | 可以一天多批处理；空闲查看界面不消耗时间 |
| 生活与开发 | 开发、饮食、睡觉、娱乐、出门、打工各至少一个有效入口 | 每个入口完成行为后状态变化与规则一致 |
| 地点 | 出租屋、书店、公园、便利店 | 可以在不见任何同伴的情况下探索并度过七天 |
| 人物线索 | 三人各有至少一个可发现的线索/候选交谈入口 | 玩家主动交谈才进入“已认识”；没有自动加入团队 |
| 生活痕迹 | 完成作品、设备变化、地点短事件中至少实现两种 | 变化在场景/图鉴/对白可被看到，读档后保留 |
| 回望 | Day 7 从日志挑选 3～5 个实际发生片段 | 没有女主、没买设备、没完成作品也能自然回顾 |

#### 三、自由相遇：状态必须拆开

建议为每个伙伴使用独立状态，勿用单一 `has_girl`：

- `unseen`：未发现，只有地点的生活线索，不自动跳剧情。
- `noticed`：玩家注意到与她有关的物件、作品或演出，但尚未交谈。
- `met`：主动触发初次交谈；此时才可解锁相应聊天入口。
- `invitable`：满足现有开发进度/剧情/关系条件后可主动邀请合作，不能自动招募。
- `recruited`：玩家确认合作，伙伴已加入项目；仍遵守其个人日程。
- `story_stage`：相遇—撞墙—迈出一步；具体门槛仍由原数值源决定。

**数据区分：**相遇、招募、约定/个人事件、当天是否在场是不同布尔/状态，不能混为一谈。

#### 四、人物线索的低成本实例（候选）

| 地点 | 不交谈时也能看到的线索 | 主动行为 | 没去怎么办 |
|---|---|---|---|
| 书店 | 折扣区的一本有铅笔批注的小册子 | 玩家查看并选择向附近的插画师搭话，才有机会认识许眠 | 在下一次书店开放时仍可发现相关线索 |
| 公园 | 长椅旁传来一段断续的旋律 | 玩家选择停下听、之后主动交谈，才可认识唐梨 | 另一个天气/时段可听见她留下的录音或再次遇见 |
| 书店/便利店 | 一张夹在书页里的台词便签 | 玩家选择阅读并追问是谁写的，才可能认识温野 | 便签可保留，玩家下次来再调查 |

不必强行把三人都放进前七天：这些是**可能出现的交互点**，真正出场可受原完成度/事件条件限制。若前七天尚无法招募，可先做到“注意到或认识”，但不破坏原门槛。

#### 五、七天的节奏不是剧情日历

- Day 1：可选任何行动；教程用轻提示，不阻挡玩家先玩作品或先离开房间。
- Day 2～3：地点和娱乐选择逐渐自然增多；引导靠玩家操作结果，不靠强制弹窗。
- Day 4～5：独立开发能力上限逐渐成为可观察的事实；不强制触发“我必须去找人”的独白。
- Day 6：玩家已有行为可产生不同的环境痕迹；不要求完成特定人际事件。
- Day 7：记录并回望实际生活。未有重大事件时可展示小事，例如读完的作品、窗外、买来的食物或深夜完成的一段代码。

#### 六、避免软锁的原则

- 不在某个日期错过一位人物后永久失去合作机会。
- 不强制刷特定一部漫画/游戏才解锁人物；作品可以成为对话话题，但不能作为唯一前置。
- 不要求本次试玩必须碰见三位同伴。
- 重要触发条件要能在 UI 看懂，或在角色行为中自然看出，不凭随机数。
- 即使未招募伙伴，也允许玩家正常睡觉、工作、开发和到达第七天。

#### 七、测试用例（可直接交给 QA / AI）

1. **纯独居路线**：七天只开发、娱乐、休息、买东西，不接触任何伙伴。可以回望自己的生活，不能假冒出现任何同伴场景。
2. **主动寻找路线**：在已开放地点主动调查线索并对话，可标记已认识，但不自动获得开发加成。
3. **先娱乐后工作路线**：娱乐作品图鉴进度、完成短评正确保存。
4. **回档路线**：先遇见一位伙伴，再读较早档，人物状态与回忆日志同步回退。
5. **多次结算路线**：一天多次使用 4 格结算器，日期/资源正确，不错误限制每日次数。
6. **无片段路线**：当日几乎无特别事件，回望降级到已发生的普通行动，不播放虚构剧情。
