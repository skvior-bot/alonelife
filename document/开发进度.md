#### 三、MVP 范围

**目标**：15~30 分钟，验证这一条链——一个人开发遇到限制 → 外出认识人 → 合作 → 自己做的游戏发生可见变化。

**做**：1 个主场景、1 个外出地点、1 个内层小关卡、1 位伙伴、1 段招募或合作剧情、1 套四格结算器、1 种敌人、基础 UI、占位美术、少量音效、存读档。

**不做**：全部 100 天剧情、完整个人支线、内层五章、全部怪物、大量收藏品、完整立绘与多方向逐帧动画。

**验收**：新游戏不靠控制台能跑完；至少一次完整的日程+合作+内层循环；资源没有非法变化；预览与结果一致；能存能读；无阻塞崩溃；经过 3 次不靠作者提示的试玩。

#### 七、主要风险

| 风险 | 应对 |
|---|---|
| 设计范围远超产能（两层游戏） | 垂直切片优先，暂缓完整章节 |
| 模拟器与策划不一致 | 每次改数先跑模拟，再改文档 |
| Godot 还没有可运行循环 | 阶段 A 不停在文档上 |
| 内层战斗存在单一最优解 | 用小规模战斗先验证策略空间 |
| 美术工作量被低估（朝向、遮挡） | 先定方向数和显示方式，再算帧 |
| 操作太频繁导致疲劳 | 批量执行 + 快速结算 |
| 真实作品名有版权风险 | 发行前改原创或取得授权 |

**五条避免返工的原则**：先做能跑的游戏再做完整系统；先验证玩家做什么再定能做多少种事；数值结论必须建立在规则正确的模拟器上；看得见的变化比隐藏倍率值钱；每个新系统都要回答"玩家获得了什么新体验"。
